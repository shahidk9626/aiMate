3. Core enquiry lifecycle

Customer message→Verify + deduplicate→Normalize event→Find tenant/contact→AI policy + context→Reply / escalate→Update CRM

The inbound event is persisted before asynchronous processing. Outbound messages are queued, retried safely and recorded. A human agent can take over at any point; takeover switches the conversation to human handling and silences the AI. The AI never invents prices, offers, availability or promises: when knowledge is missing it asks or hands off.

4. Deployment view

Application services

Separate Docker images for the Next.js web app (standalone server) and the FastAPI API. The same API image runs migrations (one-off) and, from Stage 2, the Celery worker. Containers run as non-root users and receive secrets only as runtime environment variables.

Infrastructure (pilot phase)

Single VPS running Docker Compose behind Cloudflare (DNS, TLS, WAF). PostgreSQL and Redis on the VPS with backups, or managed equivalents when volume justifies it. Encrypted secrets, logs and monitoring. Object storage from Stage 6.

MVP principle: start with a modular monolith plus a separate background worker. Avoid microservices until real load and team needs justify them.

6. Trust boundaries and non-functional requirements

Tenant isolation

Every business record is tenant-scoped. Authorization is enforced server-side on every query and mutation, and PostgreSQL Row Level Security blocks cross-tenant rows even if application code is wrong.

Webhook safety

Verify provider signatures where supported, validate payloads, deduplicate events and reject replays.

Credential security

Encrypt provider tokens at rest, redact logs, rotate secrets and restrict access.

Reliability

Idempotent jobs, retry with backoff, dead-letter handling and observable delivery states.

AI safety

Ground answers in approved business knowledge; no unsupported promises; human handoff on uncertainty.

Privacy

Retention controls, access audit, export/deletion workflows and minimal personal data collection.
